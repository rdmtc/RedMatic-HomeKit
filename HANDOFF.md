## How to work here

```
npm ci
npm test            # lint + unit tests + native scan
npm run format      # prettier + eslint --fix
UPDATE_SNAPSHOT=1 node --test test/roles.test.js test/generic.test.js   # after intentional mapping changes
```

`test/helpers/harness.js` gives you a fake Node-RED with bridge, device
node and FakeCcu in three lines; `fixtures.ccuFor('HmIP-XYZ')` loads a
device type with its paramset descriptions.

## Gotchas

- `Accessory.addService()` in `lib/accessory.js` appends a running counter
  to the subtype (`'Battery' + 3`); the generic layer overrides it with
  channel-index subtypes. Existing modules must keep the counter scheme
  (D-4).
- `SingleAccessory` defaults to **on** for multi-channel devices (as in
  3.3.0: the option is "enabled unless disabled").
- BidCos devices report `LOWBAT` on mains actuators too; the generic
  battery service is only added on BidCos when the device has no actuator
  role, on HmIP whenever `LOW_BAT` exists.
- `npm test | grep …` hides the exit code — check `$?` before committing
  (bit me once today).
